# Skill template

Adapt to the task, not mechanically. Use a lowercase English name with digits and hyphens; the description must say when to use and not use the skill. Replace fields with confirmed task information; mark unknowns unconfirmed. A blank template is not a completed skill.

```markdown
---
name: skill-name
description: Task, appropriate use and non-use.
---
# Skill title
## Goal and scope
Describe the result, when to use, and non-trigger cases.
## Inputs and sources
Required inputs, optional materials and known sources; reuse available information.
## Judgment criteria
Evidence-backed criteria, conditions and boundaries; distinguish fact, user statements, inference and unknown. Omit unsupported weights and thresholds.
## Steps
Read, judge, act and check according to dependencies; key branches include conditions, action, output and correction.
## Output
Delivery format, fields, sources and open questions.
## Examples
Authorized or clearly fictional inputs and checkable outputs, including normal and boundary cases.
## Exceptions and boundaries
Handle missing information, unavailable tools, uncertain acceptance and permissions; list forbidden actions.
```

Move longer methods and examples to references and link them from the entrypoint; add scripts or external services only when needed and verified. Check the [quality checklist](quality-checklist.en.md) and [examples](examples.en.md).

## WorkBuddy publishing fields

Add version, bilingual display names and descriptions, author and appropriate examples when required by the host. State a license only when authorized.
