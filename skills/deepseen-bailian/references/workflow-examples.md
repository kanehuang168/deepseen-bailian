# 搜和炼：可操作的模拟流程

以下内容为虚构演示，既不是实际搜索结果，也不是实际工具调用或独立验收。

## 搜：会议纪要技能
用户：帮我找一个会议纪要技能，能区分决议与讨论，标出负责人和截止时间。
路线：用户明确要求“搜”，直接检查可用已装技能和搜索工具；如无法联网，报告限制，不伪造候选链接。
假设实际取得候选正文后，按 CREATE 检查：场景是会议纪要；输入是笔记或转写；标准是区分决议和讨论、缺失日期标待确认；步骤是抽取、核对、组织；模板需包含行动项；异常是无材料时请求补充。记录来源和许可状态。
如宿主确实可调用吸星，将候选正文、来源与目标交给吸星，记录实际返回的比较及不足；不可调用时明确“未调用吸星”，仅给基于已读材料的分析。交付候选、来源、适配与缺口；不自动安装。

## 炼：客户线索判断
以下为虚构对话，不能当作任何企业的既定标准。
用户：把我判断海外采购商的经验做成技能。
助手：你最看重什么信息？
用户：采购意向、预算，以及是否愿意电话沟通。
助手：如果预算还没问到，是先补问还是直接放弃？愿意来访是必要条件吗？
用户：先补问；来访是加分，不是必要条件。
助手：请给一个继续跟进和一个暂缓的例子，并说明暂缓是否意味着永久放弃。
用户：明确有需求并愿意电话沟通的继续；问过后仍没有采购意向和预算的暂缓，之后可再评估。
根据已确认信息生成实际 SKILL.md：区分未知与明确无意向；未知预算先补问；来访只作加分；输出继续、补问或暂缓及依据和下一步。没有用户确认的行业阈值不编造。
模拟试跑：客户有需求、预算未问→补问预算，不因未提来访而拒绝；问后仍无采购意向及预算→暂缓，并标明可重新评估。再使用未用于编写的新案例验证；本文件案例不能充作独立测试。

以上只演示操作方式，不声称已经调用吸星、进行了真实对照或验证业务成效。
